Phase 1: Software & Quantitative Foundations

Duration: Weeks 1–2 | Prerequisite: None

Foundational Step

Establish fluency in Python, NumPy high-dimensional array arithmetic, Pandas DataFrame transformations, and the underlying mathematical metrics evaluated during model validation.

Core Continuous & Discrete Evaluation Metrics Exam Tested Formula Concepts
Mean Absolute Error (MAE):
MAE = (1/n) * ∑ |y_i - ŷ_i|

Linear penalty for deviations.

Root Mean Squared Error (RMSE):
RMSE = √[ (1/n) * ∑ (y_i - ŷ_i)² ]

Heavy penalty for large outliers.

RMS Logarithmic Error (RMSLE):
RMSLE = √[ (1/n) * ∑ (log(ŷ_i+1) - log(y_i+1))² ]

Penalizes under-estimation heavily.

Free Learning Resources
  • Kaggle Learn: Python, Pandas, & Intro to Machine Learning
  • MIT OpenCourseWare / Stanford CS229 (Audit Mode)
  • Great Learning: Python for Machine Learning
Competency Milestones
  • Write vector arithmetic and matrix dot products without loops
  • Perform feature aggregation and handle missing values in Pandas
  • Choose between MAE, RMSE, and AUPRC for imbalanced datasets

Phase 2: GCP Platform Literacy & Low-Code AI

Duration: Weeks 3–4 | Focus: BigQuery ML & AutoML

Exam Weight: ~13%

Decouple compute and storage on Google Cloud. Master SQL-based model development in BigQuery ML, automated hyperparameter tuning via Agent Platform AutoML, and distributed ETL pipelines via Dataflow.

Core Google Cloud Tools
  • BigQuery ML: SQL-based training for ARIMA, Logistic Regression, XGBoost
  • Cloud Storage (GCS): Storing unstructured shards and TFRecords
  • Dataflow / Dataproc: Apache Beam & Spark streaming ETL
Strategic Exam Insight

Always choose BigQuery ML or AutoML when business requirements demand minimal engineering overhead, rapid prototyping, or when data already resides natively in BigQuery tables.

Phase 3: Custom Models, Hardware & Prototyping

Duration: Weeks 5–8 | Focus: PyTorch/sklearn Containers & Accelerators

Exam Weight: ~21%

Transition from interactive Colab Enterprise notebooks to custom containerized training workloads on Artifact Registry, selection of CPU/GPU/TPU hardware topologies, and parallel distributed strategies.

Hardware Accelerator Optimal ML Workload Parallelism & Tuning
CPUs Light tabular models, small inference endpoints Multi-core threading
GPUs (NVIDIA L4/A100/H100) Deep learning, PyTorch custom containers, general matrix operations Data Parallelism (DistributedDataParallel)
TPUs (v4/v5e/v6) Ultra-large transformer models, massive matrix multiplication Model & Tensor Parallelism, bfloat16 precision

Exam Domain Mastery (~100%)

Detailed breakdown of the 6 official exam sections, key architectural competencies, and scenario expectations.

Section 1 ~13% Weight

Architecting Low-Code AI Solutions

  • Developing ML models using BigQuery ML (ARIMA, XGBoost, Linear/Logistic Regression).
  • Feature engineering and predictions inside BigQuery using standard SQL.
  • AutoML tabular, image, and text models on Gemini Enterprise Agent Platform.
  • Selecting pre-built AI APIs (Document AI, Vision API, Translate API).
Exam Rule of Thumb: If a scenario asks for rapid time-to-market with tabular data in BigQuery without exporting data, choose **BigQuery ML**.
Section 2 ~16% Weight

Managing Data & Models Across Teams

  • Data exploration and preprocessing tools (BigQuery, Dataflow, Apache Spark, Pandas).
  • Creating and serving central features using Agent Platform Feature Store.
  • Collaborative secure notebooks (Colab Enterprise, Agent Platform Workbench).
  • Tracking artifacts, lineage, and experiment iterations using ML Metadata.
Privacy First: When handling PII or sensitive training data, integrate Cloud DLP (Data Loss Prevention) before feature store ingestion.
Section 3 ~21% Weight

Scaling Prototypes into ML Models

  • Building models considering cost, latency, interpretability, and scale.
  • Packaging PyTorch, sklearn, or custom frameworks into Artifact Registry Docker images.
  • Selecting GPU vs. TPU compute clusters for high-performance training.
  • Implementing Data Parallelism and Model Parallelism across accelerator pods.
Compute Selection: Use **TPUs** for large matrix-heavy transformer models; use **GPUs** for general custom PyTorch/TensorFlow deep learning.
Section 4 ~20% Weight

Serving and Scaling Models

  • Deploying online inference endpoints vs. non-real-time batch prediction jobs.
  • Registering model versions in Gemini Enterprise Agent Platform Model Registry.
  • Executing canary rollouts, A/B testing, and traffic split percentages.
  • Optimizing inference containers on Cloud Run or Google Kubernetes Engine (GKE).
Deployment Strategy: Never shift 100% traffic immediately to a newly trained model. Always configure canary split (e.g. 10/90) with metric monitoring.
Section 5 ~18% Weight

Automating & Orchestrating ML Pipelines

  • Building end-to-end pipelines using Agent Platform Pipelines / Kubeflow.
  • Establishing automated retraining triggers based on schedule or performance degradation.
  • Deploying models within CI/CD/CT pipelines using Cloud Build.
  • Maintaining consistent preprocessing code between training and serving.
CT (Continuous Training): Automation must ensure data skew is checked prior to triggering expensive retraining pipelines.
Section 6 ~13% Weight

Monitoring & Securing AI Solutions

  • Monitoring for Training-Serving Skew, Data Drift, and Concept Drift.
  • Securing AI solutions against prompt injection, data exfiltration, and malicious queries using **Model Armor**.
  • Configuring model explainability and feature attributions (Agent Platform Inference).
  • Evaluating Generative AI outputs using LLM-as-a-judge and Gen AI Evaluation Service.
Drift Definitions: **Data Drift** = shift in input feature distribution; **Concept Drift** = shift in statistical relation between inputs and ground truth target.
